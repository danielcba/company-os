## Discoveries

### The canon can be enforced in code by naming and contracting modules after concepts.

Every module in `app/` mirrors one cognitive concept and obeys its Cognitive Contract (Input → Transformation → Output), taken verbatim from the concept files.

The mapping is direct:

- `observations.py` — Observation: capture facts without interpretation; observations are frozen (immutable).
- `evidence.py` — Evidence: organize observations; Quality Classes Q1–Q4 with weight ranges.
- `context.py` — Context: select the most coherent mental model.
- `pattern.py` / `anomaly.py` — recurrence and deviation.
- `hypothesis.py` — candidates with an explicit falsification criterion (Popper).
- `insight.py` — restructuring (LLM or heuristic producer is tagged).
- `confidence.py` — the Calibration Model, computed, never intuited: `L = L0 + Σ wᵢeᵢ`, `S = 1/(1+e⁻ᴸ)`, `C_final = [α·S + (1−α)·C]·(1−ECE)`.
- `recommendation.py` / `decision.py` — a Decision is a falsifiable prediction.
- `memory.py` — PLANNED in the canon: a placeholder that refuses to run, never an operational capability.

### Memory is enforced as planned, not just annotated.

The placeholder raises by design. The code cannot drift into implementing a concept the canon declares future.

### The project rule holds.

Single source of truth: the canon is read from the submodule, never copied. No divergent duplicate exists.

## Decisions

- Create `company-os-monitor` as the implementation repository (sibling, not child, of `company-os-main`).
- Link the canon via git submodule pinned to the current canonical commit.
- Name every module after its cognitive concept and honor its Contract verbatim.
- Declare Memory as planned in code (placeholder that refuses to run).
- Deliver the COS-Monitor prompt to drive the full implementation within this skeleton.

## Addendum — SAP R/3 Integration Recorded as External Capability

### Files changed

- `decisions/decisions.md` — added D-2026-08-07: the SAP R/3 integration of
  `company-os-monitor` is declared an external, non-canonical capability.

### Context

A full audit of the first implementation flagged that the SAP gateway in
`company-os-monitor` had no canonical decision behind it, violating E2, E5 and
R9. The audit recommended registering the integration so the code stops
inventing architecture.

### Decision

The integration is documented in the Decisions log as D-2026-08-07: it is an
external capability, not a cognitive concept. Transport via PyRFC, cost formula
`cost = hours_down * rate_per_hour`, posting via
`BAPI_ACC_ACTIVITY_ALLOC_POST` with mandatory `BAPI_TRANSACTION_COMMIT`
`/ROLLBACK`, weighted metrics, and a mock mode.

### Consequence

The canon now guides the integration instead of the integration drifting from
the canon. Traceability restored (E5); no concept slot claimed (E2); the code
adapts to the architecture (R9).
