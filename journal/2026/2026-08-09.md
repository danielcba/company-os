## Discoveries

### A product can wrap the cognitive core without diluting it.

The canonical flow is the brain. Agents, dashboard, alerts, reports,
authentication and the LLM client are external capabilities around it. The same
rule that governed SAP R/3 (D-2026-08-07) governs the whole product surface:
label it external, keep it out of the Cognitive Lexicon, and let the canon
guide it.

### The name is a governance instrument.

The product keeps the name `company-os-monitor`. No alternative brand enters
the canon. A stable name anchors the mapping between blueprint, code, and
canon.

---

## Decisions

- Adopt the product blueprint as the specification of the product layer of
  `company-os-monitor` (agents, API, dashboard, alerts, reports, auth, LLM).
- Record D-2026-08-09 and ADR-0002: the product is COS-Monitor; external
  capabilities follow the blueprint-before-code rule.
- Keep the cognitive core (`app/`) intact; label all product components as
  external, non-canonical capabilities.
- Memory stays planned: the product must not implement it as operational.

## Addendum — Product Layer Implemented and Verified

The blueprint is now code. The product surface was built around the intact
cognitive core (`app/`) and verified end-to-end.

### Progress

- `product/` package implemented: `config`, `db` (asyncpg + idempotent schema),
  `auth` (JWT + bcrypt, seeded tenant `demo`/`admin`), `api` (FastAPI:
  `/auth/login`, `/health`, `/metrics`, `/api/dashboard`, `/reports`,
  `/rules`), agents (`linux` SSH, `windows` WMI), services (`ingest`, `analysis`,
  `alerts`, `reports`, `llm`), templates (login + dashboard) and static assets.
- Schema extended: `tenants`, `users`, `servers`, `events`, `alert_rules`,
  `alerts`, `reports`, `predictions` (all idempotent, indexed).
- Deployment: `docker-compose.yml` (db + redis + api on `:8000` + one-shot
  `app`), `Dockerfile` (uvicorn + libpango for WeasyPrint), `start.sh` waits for
  healthy db, schema and API `/health`.
- The canonical flow (`app/`) runs unchanged against real ingested data through
  `product/services/analysis.py`, measuring deviation **per metric** so one
  healthy pattern cannot mask a violated one.

### Verification

- 18 tests passed (cognitive smoke + product suite).
- Docker end-to-end: `/health` 200; login OK (bad credentials → 401); ingest
  `cpu=95` → anomaly `Deviation 0.19 from pattern 'cpu<80'`, decision
  `investigate`, confidence labeled `not calibrated`; dashboard shows the
  server ROJO with the triggered alert; executive PDF report generated and
  downloaded (valid `%PDF`).

### Discoveries

- asyncpg does not serialize Python `dict` into a JSONB parameter: events
  require an explicit `json.dumps`.
- The login form initially used the htmx `json-enc` extension, whose script is
  a separate file that was never loaded: the browser sent form-urlencoded and
  the JSON endpoint returned 422 silently. Replaced with a direct `fetch`
  (JSON body, visible error messages) — the login now works.

### Files changed (implementation repo `company-os-monitor`)

- `product/`, `tests/test_product_*.py`, `pyproject.toml`,
  `data/schema.sql`, `Dockerfile`, `docker-compose.yml`, `start.sh`,
  `README.md`, `USER_GUIDE.md`, `docs/PRODUCT_BLUEPRINT.md`.

### Consequence

Traceability holds: the blueprint (this entry, D-2026-08-09, ADR-0002) was
recorded first; the code implemented it after. No new concept was claimed by
the product surface; it remains external, non-canonical capability.
